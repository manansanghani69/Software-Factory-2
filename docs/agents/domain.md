# Domain Docs

## Layout

This repo uses a single context:
- `GLOSSARY.md` at the repo root.
- Architecture decision records under `docs/adr/`.

## Before exploring

Read the root glossary and ADRs relevant to the work.
If `GLOSSARY-MAP.md` exists, follow it to the relevant
context glossaries and context-scoped ADRs instead.

If these files are absent, proceed silently.
Domain-modeling creates them when terms or decisions
are resolved; setup does not create empty placeholders.

## Vocabulary

Use glossary terms in issue titles, proposals,
hypotheses, and tests. For a missing concept, reconsider
the terminology or note the gap for domain-modeling.

## Decisions

Explicitly flag any proposal that contradicts an ADR,
identify the decision, and explain why to reopen it.

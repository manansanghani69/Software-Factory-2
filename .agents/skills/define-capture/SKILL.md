# Define capture

Use for the bounded Capture stage. Read [the operating contract](../project-definition-system/references/operating-contract.md), [the artifact handbook](../project-definition-system/references/artifact-handbook.md), [the glossary](../project-definition-system/references/terminology.md), and the [project brief template](../project-definition-system/templates/project-brief.md).

At startup, read the project index and existing brief/source index if present. Preserve the raw request and provenance; a previous chat or handoff is not authority. Work on this intake session only.

## Work

1. Record every supplied source, link, attachment, and relevant existing artifact. Preserve wording where it carries intent or uncertainty.
2. Normalize actors, present situation, requested change, evidence, assumptions, contradictions, and unanswered questions. Separate observed facts from proposals.
3. Classify the effort as greenfield, substantial feature, or bounded change. Identify artifacts that can be reused and check their currency.
4. Write or update the intake/project brief and source index. Keep missing decisions visible; do not turn a proposed solution into an established need.

## Output and completion

Persist the intake, provenance, work classification, source links, contradictions, and missing decisions. Complete when every supplied material is represented or linked, contradictions are visible, and no invented certainty replaces the raw request.

End with a handoff containing changed files, settled evidence, open questions/fog, blockers, latest valid gate, and the prepared manual invocation:

```text
Run $define-frame for <project>. Read the intake, source index, and listed evidence. Resolve one coherent Intent brief with the human, then record the Intent Gate result and hand off the next valid action.
```

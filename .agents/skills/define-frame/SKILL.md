# Define frame

Use for the bounded Frame stage. Read [the operating contract](../project-definition-system/references/operating-contract.md), [the artifact handbook](../project-definition-system/references/artifact-handbook.md), [the glossary](../project-definition-system/references/terminology.md), and [the integration adapters](../project-definition-system/references/integration-adapters.md). Start with the intake, source evidence, and current project index. Retrieve environmental facts yourself.

## Work

1. Build a coherent brief covering target actors, present problem/baseline, why now, desired outcome and success signal, constraints, appetite, assumptions, and explicit exclusions.
2. Use the installed grilling and domain-modeling skills when available: ask the current human decision frontier, recommend answers, sharpen terms, and test concrete scenarios. Do not answer the human's questions on their behalf.
3. Link evidence and distinguish facts, assumptions, proposals, and unresolved questions. Route consequential unresolved choices to a Decision Ticket or scoped fog.
4. Present the brief for the human's Intent Gate result. Record `pass`, `revise`, `spike`, `defer`, or `stop`, the human/date, reasons, conditions, authorized work, and immutable artifact revision. Record no pass without an explicit human result.

## Output and completion

Persist the project brief and Intent Gate record. Complete when the human has chosen a gate result against a coherent brief and the result names the responsible next action. A pass authorizes discovery/shaping within the intent only.

End with the [session handoff](../project-definition-system/templates/session-handoff.md) and a prepared manual invocation for the chosen outcome, commonly:

```text
Run $define-wayfinder-chart and/or $define-domain-model for <project or selected slice>. Read the passed Intent brief and current evidence. Keep the next session bounded to one map/model frontier and preserve the approval revision.
```

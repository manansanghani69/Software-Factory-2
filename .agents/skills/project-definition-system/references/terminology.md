# Project Definition System glossary

**Project**: The complete effort under definition, including intended outcomes and scope boundaries.

**Outcome**: A measurable change in a user's or business's situation that justifies the work.

**Planning Stage**: A bounded step in the definition process with inputs, outputs, and an exit condition. Avoid “phase” for a process step.

**Delivery Slice**: A bounded vertical portion of a project with its own outcome, scope, definition, and acceptance conditions.

**Capability**: A durable ability the product or system provides in support of an outcome.

**Feature**: A coherent part of a capability with identifiable user-visible or system-visible behavior.

**Story**: An independently understandable behavioral portion of a feature, with rules and concrete acceptance examples.

**Task**: A bounded piece of implementation work serving a Story or another approved scope node.

**Subtask**: A smaller implementation unit within a Task when further decomposition adds useful meaning.

**Appetite**: The amount of time, cost, or complexity the human is willing to invest in a selected slice; it constrains selection rather than predicting effort.

**Decision Map**: An index of questions and decisions that makes the route to a named destination visible.

**Delivery Map**: Decomposition of intended and approved work into meaningful scope nodes, with slice boundaries and links to definitions.

**Scope Node**: An identifiable Delivery Map element with one decomposition parent and potentially several dependencies.

**Decision Ticket**: A precise question or investigation whose resolution advances the Decision Map.

**Container Issue**: An issue representing a scope grouping and progress, not executable implementation work.

**Execution Issue**: An issue authorizing a defined implementation unit with acceptance and verification guidance.

**Frontier**: Unresolved decisions whose prerequisites are settled and which are available to work now.

**Fog**: Recognized in-scope uncertainty that cannot yet be stated as a precise decision question.

**Implementation Discretion**: An explicitly allowed choice that cannot change approved material behavior, scope, contracts, or acceptance.

**Spike**: A bounded investigation or disposable experiment with a precise learning question and exit condition.

**Document Manifest**: Assessment of required artifacts for a slice, including deliberate skips and reasons.

**Gate**: A human decision boundary authorizing the next commitment using linked evidence.

**Baseline**: An approved version of selected scope and definitions. Material changes require impact review.

**Material Change**: A change to outcomes, boundaries, behavior, contracts, acceptance, significant constraints, or consequential dependency order.

**Definition Complete**: A selected slice has approved material behavior and boundaries, with residual uncertainty classified explicitly.

**Readiness**: An approved definition has a coherent, traceable, verifiable issue set and usable dependency order.

**Readiness Record**: Evidence, human approval, document revisions, and candidate issue set authorizing implementation.

**Stale**: Content or work whose former approval no longer applies because a prerequisite changed.

**Traceability**: Ability to follow an execution issue through examples, definition, scope, and outcome, and reverse-trace affected work.

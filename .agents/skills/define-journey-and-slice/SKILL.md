# Define journey and slice

Use for one bounded shaping/selection session. Read [the operating contract](../project-definition-system/references/operating-contract.md), [the artifact handbook](../project-definition-system/references/artifact-handbook.md), [the glossary](../project-definition-system/references/terminology.md), [the integration adapters](../project-definition-system/references/integration-adapters.md), and the [slice template](../project-definition-system/templates/slice-definition.md). Start from accepted intent, domain/journey evidence, existing Decision Maps, and macro solution options.

## Work

1. Map the whole journey at broad resolution. Include important actors, variants, exceptions, risks, and later fog without prematurely defining every implementation detail.
2. Sketch the macro solution and candidate coherent vertical slices. For each candidate record outcome, boundary, exclusions, dependencies, evidence, appetite, reversibility, risk, and opportunity cost.
3. Compare the next candidates using structured human judgment. Keep later slices as direction/proposals, not current truth.
4. Persist the selected slice, scope baseline, alternatives, and evidence. Record the human Slice Gate result with human/date, immutable revision, reasons, conditions, and authorized next work. A pass authorizes definition of that boundary, not implementation.

## Output and completion

Complete when the selected slice is coherent and independently verifiable, alternatives are visible, later work/fog remains visible, and the human has chosen a Slice Gate result. If no selection is made, persist the candidates and stop at the gate.

End with a handoff and a prepared manual continuation, commonly:

```text
Run $define-document-manifest for <selected slice>. Read its Slice Gate revision, scope baseline, current definitions, and change/risk evidence. Assess every documentation dimension and choose the next definition frontier.
```

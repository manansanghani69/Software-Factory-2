Lesson 0002

Branch Strategies

Keep the agent's work off the main line — and make re-runs safe.

Recall before reading

Close the reference. From memory, write down the three branch strategies and which one docker() defaults to. Then read on — the answers are in the table below.

Why this matters

A real autonomous pipeline can't have agents writing straight into your working directory. You need to know where an agent's commits land, why, and which strategy survives running many agents at once — that's the difference between a demo and a factory.

The three strategies

StrategyWhat happensWhen to use it
{ type: "head" } Agent writes directly into the host working directory. No worktree, no branch. Scratch repos, one-off exploration. Never for the pipeline.
{ type: "merge-to-head" } Temp branch in a git worktree; agent works there; merged back to HEAD at the end, temp branch deleted. A safe one-shot when you want the result on your current branch but nothing left behind.
{ type: "branch", branch: "agent/x" } Worktree on a real named branch; commits land on agent/x. Re-running with the same name reuses the worktree and fast-forwards from origin when safe. Parallel agents, PR-style workflows, repeated runs on the same task. Don't run agents on your main line, keep them pointed at named branches.

Defaults: head for bind-mount providers, merge-to-head for isolated providers. (README: How it works)

Why branch re-runs are safe

Re-running { type: "branch", branch: "agent/x" } reuses the existing worktree instead of piling up temp worktrees. It fast-forwards from origin when safe, so a stale worktree doesn't fight itself across runs. Decision logged in ADR 0003.

Use it

Your main.ts, changed from lesson 0001 to the pipeline-safe version:

import { run, opencode } from "@ai-hero/sandcastle";
import { docker } from "@ai-hero/sandcastle/sandboxes/docker";

const result = await run({
  agent: opencode("opencode/big-pickle"),
  sandbox: docker(),
  promptFile: ".sandcastle/prompt.md",
  branchStrategy: { type: "branch", branch: "agent/fix-42" },
  maxIterations: 5,
});

console.log(result.branch);        // "agent/fix-42"
console.log(result.commits);       // the agent's work, on that branch

Run it, then run it again with a change to prompt.md. On the second run you'll see the worktree get reused rather than rebuilt — that's ADR 0003 in action.

Built-in prompt args for branch work

When your prompt comes from a promptFile, Sandcastle injects two values you don't have to supply: {{SOURCE_BRANCH}} (the branch the agent works on) and {{TARGET_BRANCH}} (your host's active branch). Put them in your prompt so the agent diffs against the right base:

You are working on {{SOURCE_BRANCH}}.
When you diff your changes, compare against {{TARGET_BRANCH}}.
Fix issue #42 and finish by printing <promise>COMPLETE</promise>.

Two gotchas to remember: this substitution applies only to promptFile — inline prompt strings are passed literally, and passing promptArgs alongside an inline prompt is an error. (README: prompts)

Never run these in parallel

head and merge-to-head are not safe for concurrent agents: head shares the host working directory across all of them, and merge-to-head races git merge against the same HEAD. Parallel fan-out requires each agent to get its own distinct named branch — that's the branch strategy. (ADR 0018)

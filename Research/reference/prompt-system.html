Prompt System

How promptFile, promptArgs, and shell expansion compose.

Prompt resolution

Exactly one of: prompt (inline string, passed literally) or promptFile (path to file, subject to substitution). Both provided = error. Neither provided = error.

Execution order

  1. promptArgs substitution — all {{KEY}} placeholders replaced on the host, including inside shell expressions.
  2. !`command` expansion — shell commands run inside the sandbox after sandbox.onSandboxReady; their stdout replaces the expression.
  3. Final prompt sent to the agent.

All shell expressions in a prompt run in parallel. Non-zero exit = run fails immediately.

Built-in prompt arguments

PlaceholderValue
{{SOURCE_BRANCH}}Branch the agent works on (per branch strategy)
{{TARGET_BRANCH}}Host's active branch at run() time

Cannot be overridden via promptArgs — passing them is an error.

promptArgs rules

  • {{KEY}} with no matching arg → error, run stops.
  • Extra arg with no matching placeholder → warning, execution continues.
  • !`…` inside an argument value is inert — not executed against the shell. Safe for user-authored content (issue bodies, PR descriptions).
  • promptArgs alongside an inline prompt string → error. Use promptFile.

Completion signal

Default: <promise>COMPLETE</promise>. Override via completionSignal (string or array). The signal must be documented in the prompt for the agent to know to emit it. result.completionSignal reports which signal matched.

One-liner

import { run, claudeCode } from "@ai-hero/sandcastle";

await run({
  agent: claudeCode("claude-opus-4-8"),
  promptFile: ".sandcastle/prompt.md",
  promptArgs: { ISSUE_NUMBER: "42" },
  completionSignal: ["TASK_COMPLETE", "TASK_ABORTED"],
});

Prompt file example

You are working on {{SOURCE_BRANCH}}. Compare against {{TARGET_BRANCH}}.

#\`gh issue view {{ISSUE_NUMBER}} --json body -q '.body'\`

#\`git log --oneline -10\`

Fix the issue. When done, print <promise>COMPLETE</promise>.

Sandbox Providers & Branch Strategies

The two knobs that decide where the agent lives and how its work reaches git.

Sandbox providers

Every run() / interactive() / createSandbox() call takes exactly one sandbox. Providers come from subpath imports.

ProviderImport pathIsolationUse it when
docker()@ai-hero/sandcastle/sandboxes/dockerBind-mountLocal dev default; worktree dir is mounted into the container, writes land directly on the host FS
podman()@ai-hero/sandcastle/sandboxes/podmanBind-mountRootless containers on Linux without Docker Desktop
vercel()@ai-hero/sandcastle/sandboxes/vercelIsolated (microVM)Cloud runs, no local Docker; the repo is copied in, output synced back
noSandbox()@ai-hero/sandcastle/sandboxes/no-sandboxNoneAgent runs directly on the host; wt.interactive() defaults to this

Docker options you'll actually use

docker({
  imageName: "sandcastle:local",              // built by `sandcastle init`
  mounts: [
    { hostPath: "~/.npm", sandboxPath: "/home/agent/.npm", readonly: true }, // cache reuse
  ],
  env: { DOCKER_SPECIFIC: "value" },   // merged at launch
  network: "my-network",               // string or string[]
  groups: ["docker", 999],              // --group-add (e.g. a bind-mounted socket)
  cpus: 2,                             // --cpus limit
})

Branch strategies

Control how the agent's commits relate to branches. Bind-mount providers default to head; isolated providers default to merge-to-head.

StrategyWhat happensBest for
{ type: "head" }Agent writes straight into the host working directory. No worktree, no branch.One-shot exploration on a scratch repo
{ type: "merge-to-head" }Temp branch in a git worktree; agent works there; merged back to HEAD at the end; temp branch deleted.Safe default for host repos you don't want polluted
{ type: "branch", branch: "foo" }Worktree on a real named branch; commits land on foo. Re-running with the same name reuses and fast-forwards the worktree (ADR 0003).Parallel agents, PR-style workflows, review pipelines
Mental model

For bind-mount providers the worktree directory is mounted into the container, so the agent writes straight to your disk through the mount — no sync step. For isolated providers (Vercel), the repo is copied into the sandbox and changes are synced back.

One-liners

import { run, claudeCode } from "@ai-hero/sandcastle";
import { docker } from "@ai-hero/sandcastle/sandboxes/docker";

await run({
  agent: claudeCode("claude-opus-4-8"),
  sandbox: docker(),
  promptFile: ".sandcastle/prompt.md",
});

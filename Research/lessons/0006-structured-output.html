Lesson 0006

Structured Output

Turn agent prose into typed, validated data your orchestrator can branch on.

Recall before reading

From lesson 0005: what must an agent provider support to use fork()? Keep that answer in your head — the same constraint shows up again in this lesson, in a different shape.

Why this matters

Until now your prompts end in commits — great for fixing issues, useless for deciding. When an agent needs to tell your pipeline "these three issues are independent, here's my plan for each," you can't parse prose reliably. Structured output makes the agent emit JSON in a known tag, and Sandcastle validates it against a schema before your code ever sees it.

The pattern: prompt says the shape, schema guarantees it

You write `…` into the prompt as the container for the answer, and pass an Output.object() with a Standard Schema validator (Zod here — Valibot and ArkType work identically):

import { run, Output, claudeCode } from "@ai-hero/sandcastle";
import { docker } from "@ai-hero/sandcastle/sandboxes/docker";
import { z } from "zod";

const result = await run({
  agent: claudeCode("claude-opus-4-8"),
  sandbox: docker(),
  prompt: `Analyze the code. Output JSON inside <result> tags.
    The result must match this schema:
    { summary: string; score: number }
  `,
  output: Output.object({
    tag: "result",
    schema: z.object({ summary: z.string(), score: z.number() }),
  }),
});

console.log(result.output.summary); // typed as string
console.log(result.output.score);   // typed as number

Output.string({ tag }) is the lighter sibling — it returns the tag's contents trimmed, with no JSON parsing. (README: structured output)

The rules

  • maxIterations must be 1 (the default). Structured output only works on a single-iteration run.
  • The resolved prompt must contain the opening tag literal (e.g. the text <result>). If it's missing, extraction has nothing to anchor on.
  • Validation happens against the schema before your code runs — a malformed payload never reaches you.
Failure is loud

When extraction or validation fails, run() throws a StructuredOutputError carrying tag, rawMatched, cause, commits, branch, preservedWorktreePath — and, when a session was captured, the sessionId you need to resume the run and ask for a corrected answer.

Retries come with a provider constraint

Set maxRetries: 2 and Sandcastle handles the loop for you: each retry resumes the same session and feeds back a token-efficient description of the validation error, so the agent re-emits a corrected tag without redoing its work:

const result = await run({
  agent: claudeCode("claude-opus-4-8"),
  sandbox: docker(),
  prompt: "Analyze the code and emit JSON inside <result> tags.",
  output: Output.object({
    tag: "result",
    schema: z.object({ summary: z.string(), score: z.number() }),
    maxRetries: 2,
  }),
});
Not every provider can retry

Retries resume the agent session, so maxRetries > 0 only works with providers that support session resumption — claudeCode(), codex(), pi(). Calling it against opencode(), copilot(), or cursor() throws immediately. This is the same constraint you saw shape fork() in lesson 0005: session control is a resumable-provider superpower.

If you're on a resumable provider and want a custom retry loop (a different feedback prompt, model rotation), drive it yourself with resumeSession: catch the StructuredOutputError, read its sessionId, and re-run asking the agent to re-emit inside the tag.

Where you've already seen this: the planner

The parallel-planner templates in sandcastle init import Zod for their <plan> output schema — the planner agent emits a validated plan (which issues are parallelizable, in what order), and main.mts branches on result.output to decide what to run where. Structured output isn't a toy: it's how the factory decides its own work. (README: templates)

Do it now

  1. Write a prompt that asks the agent to analyze your repo and emit JSON inside <result> tags with a shape you define.
  2. Add an output: Output.object({ tag: "result", schema: z.object({ ... }) }) to a run() call. Split the schema's shape into the prompt so the agent knows what to emit.
  3. Run it and console.log(result.output) — you should get clean typed fields, not prose.
  4. Deliberately break the schema (e.g. ask for a number you know the agent will emit as a string) and catch the StructuredOutputError. Read its fields — including rawMatched.
